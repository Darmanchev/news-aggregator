# News MVP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. User authorized execution in this session.

**Goal:** Run a real Bulgarian news aggregator using permitted RSS content.

**Architecture:** MERN with TypeScript, organized as a modular monolith. React lives in `apps/web`; Express and the collector live in `apps/api`. MongoDB stores article metadata. Start with Mediapool; other publishers remain disabled pending reuse review.

**Tech Stack:** Node.js 22.22.2+ on the 22 line (or 24.15+ / 26+), Express 5, React, Vite, Mongoose, rss-parser, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-20-news-mvp-design.md`; the feature-module structure discussed after that document replaces its flat server layout.

## Global constraints

- Trusted, configured RSS sources only; no public ingestion endpoint.
- HTTP(S) article links, plain text output, bounded feeds, request timeout.
- Unique source/external ID, preserved first-seen date, stable cursor pagination.
- Bulgarian keyword tags; no required AI, accounts, ads, scraping, or photos.
- Collect separately from the web process; continue on source failures.
- No existing Git repository: work directly in the user-provided empty folder; no commits or worktree operations.

## Review focus

- Cyrillic word boundaries must not behave like ASCII-only word boundaries.
- Invalid cursors, arrays, unknown filters, and oversized limits return 400.
- A publisher failure must not delete articles or interrupt other sources.
- Late frontend responses must not replace a newer selected filter.
- Unknown API paths must not return the frontend HTML.
